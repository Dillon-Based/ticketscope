- {claim: "Only the NEW streamlined sign-up ('new AWS experience', projects) assigns one of us-east-2/eu-north-1/ap-southeast-2 by contact-address country; changing contact info does not change it. Users needing a specific Region should use 'Sign up for AWS (advanced)' or activate advanced features to select different Regions. Also: the restriction applies only to the new streamlined path, not to all new sign-ups.
- Implication: ACM for ALB must be in the same Region as the ALB (fine); CloudFront certs in us-east-1 would be affected (not needed here).

## D. LBC Gateway + external-dns + ACM + deletion: verdict WEAKENED (cert and deletion claims)
- GA: {claim: "AWS announced GA of LBC Gateway API support (L4 -> NLB, L7 -> ALB)", source: https://aws.amazon.com/blogs/networking-and-content-delivery/aws-load-balancer-controller-adds-general-availability-support-for-kubernetes-gateway-api, publisher: AWS Networking blog, pub_date: 2026-03-06, confidence: high}. But LBC L7 docs say ALB implementation does not fully implement Core; examples mix v1beta1/v1 and ListenerSets are experimental (https://kubernetes-sigs.github.io/aws-load-balancer-controller/latest/guide/gateway/l7gateway/, undated, confidence medium).
- One ALB per Gateway: confirmed by L7 docs (same URL), confidence high.
- Certificate: L7 docs say listener CertificateRefs unsupported ("Use LB Config"); the example sets defaultCertificate ARN in LoadBalancerConfiguration. Survives. Counter-evidence: AWS blog says the controller "queries ACM and attaches the certificate that matching the hostname" with no manual ARN (blog, 2026-03-06, confidence medium; fetch was truncated). The two sources conflict; ACM discovery may exist, so explicit ARN may not be strictly required, but explicit ARN is the documented path and the safer one. Ingress-era precedent: without cert annotation controller makes HTTP:80 listener only (https://github.com/navapbc/agentic-development-platform/pull/56) and wildcard cert not auto-attached (https://github.com/kubernetes-sigs/aws-alb-ingress-controller/issues/961, old). No Gateway-specific "listener without cert" bug found.
- external-dns: {claim: "gateway-httproute source takes targets from parent Gateway Status.Addresses unless the external-dns.kubernetes.io/target annotation overrides; addresses of type unset, IPAddress or Hostname are used; route must be Accepted; Gateway Programmed is not checked.", source: https://raw.githubusercontent.com/kubernetes-sigs/external-dns/master/source/gateway.go, publisher: kubernetes-sigs/external-dns source, pub_date: master as of 2026-11-12, confidence: high (via fetch summary)}. The docs page itself does not mention status.addresses and its AWS example puts an ALB hostname in a Gateway target annotation (https://kubernetes-sigs.github.io/external-dns/latest/docs/sources/gateway-api/, confidence medium). Also external-dns creates both A and AAAA aliases for dualstack ALBs.
