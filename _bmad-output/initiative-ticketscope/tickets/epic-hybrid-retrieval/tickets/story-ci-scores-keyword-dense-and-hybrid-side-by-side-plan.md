## Intent

**Problem:** The eval Job passes no embedder, so dense and hybrid are skipped and the baseline and README carry keyword only (R4).

**Approach:** The eval Job loads the baked model, embeds each query live inside the timed search, and scores dense and hybrid beside keyword on every pair. The Job's deadline is checked against the measured run and raised. `eval/baseline.json` is then replaced whole by a CI run's results and the README table regenerated by the existing script.

</intent-contract>

- Given a PR, when the eval Job runs, then the eval artifact holds Recall@1/5/10, MRR@10 and p95 for keyword, dense and hybrid split short, log_heavy and overall, with the lineage's model id.
- Given the updated baseline, when the gate runs, then it passes, and fails a deliberately regressed dense ranking.
- Given the baseline, when the README check runs, then it passes and shows all three modes.

## Implementation Notes

Oneshot: the product change is ~40 lines (score takes an embedder, eval main builds it, the Job gets the model env and memory); the rest is tests and chart or workflow limits.

- `src/ticketscope/jobs/eval/score.py`, `main.py`: `score(store, pairs, embedder=None)`; `build_embedder` returns the baked FastEmbed model when `TICKETSCOPE_EMBEDDING_MODEL_ID` is set, else none (dense and hybrid stay skipped). Query embedding stays inside the timed search, so dense p95 is honest.
- `deploy/charts/ticketscope`: the eval Job gets the model env and its own `eval.resources` (1Gi limit); the old test that the eval Job never gets the model is replaced.
- Measured on local kind (Docker Desktop) with the pinned 2026.11.1 asset: wall 1475.1 s, all three modes scored, scores equal spike 3.3's (dense 0.796/0.579, hybrid 0.817/0.594, keyword 0.771/0.550 Recall@10/MRR@10). That is too close to 1800 s for a slower runner, so `eval.activeDeadlineSeconds` is 2700, `kind-up.sh` Helm timeout for eval 50m, `_kind-deploy.yml` job timeout 75 min.
- `tests/eval/test_eval_kind.py`: kind checks that all three modes are scored on every pair and that wall seconds are under the Job's deadline (the summary already prints wall seconds).
- Not done here: the baseline and README. A changed baseline must equal the PR's own CI results (epic-eval-gate provenance), so it can only be committed from a CI run of this change. Owed as operator actions.
