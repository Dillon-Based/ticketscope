# The eval baseline is CI output only, committed in a follow-up PR

The regression gate compares each PR's eval results with `eval/baseline.json`, so the baseline has to be numbers a CI run produced. We decided that `eval/baseline.json` is the full CI results JSON (lineage and every reported metric), that a changed baseline must equal the PR's own CI results within the 0.005 tolerance, and that the gate passes with a "no baseline" report when none exists, so the first baseline was committed by a follow-up PR (#29, `17c3dd1`) from the artifact of the gate PR's own run (#28, `b26574b`, run 42526527850). The reason, from the story 2.3 plan (`story-a-regressing-pr-cannot-merge-plan.md`, Boundaries and Design Notes): baseline numbers must never be hand-written, and the gate step runs in the same job that produces them, so the first PR cannot already carry a matching baseline. This is hard to reverse because the README table renderer, the gate and the provenance check all depend on the baseline's shape.
