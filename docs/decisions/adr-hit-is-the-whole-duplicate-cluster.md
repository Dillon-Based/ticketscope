# A retrieval hit is any member of the query's whole duplicate cluster

Eval needs a definition of "relevant" for each query issue. Story 2.1 scored against the single linked target; we decided instead that a query's relevant set is its duplicate cluster (the connected component over every in-subset duplicate link, in both directions, minus the query), computed in `core` when the pairs are derived and stored in each pairs-file line as `relevant`. Recall@k counts a hit when any member is in the top k, and MRR@10 uses the first member's rank. The reason, from the story 2.2 plan (`story-scores-count-the-whole-duplicate-cluster-split-by-ticket-kin-plan.md`, Design Notes, commit `9a62dbc`): cluster links exist only in the snapshot, not in the loaded corpus, so eval cannot derive them at run time, and the 2.1 target-only path was deleted rather than kept behind a flag. Changing this definition changes every score and invalidates the committed baseline.
